# TECHNICAL DOCUMENTATION
## Web-Based Visual Schedule, Task Management and Communication System

### 1. Project Overview

The Web-Based Visual Schedule, Task Management and Communication System is a web-based application developed to assist caregivers, therapists, and teachers in managing children's daily activities, schedules, tasks, progress, and communication resources.

The application uses PHP for server-side processing, MySQL/MariaDB for database management, HTML and CSS for interface development, and JavaScript for client-side interactions.

The project is developed and tested locally using XAMPP and phpMyAdmin. GitHub is used for source code management and team collaboration.

### 2. Project Objectives

The system aims to:

1. Provide an organized platform for managing child profiles.
2. Allow users to create and manage visual schedules.
3. Support task assignment and completion monitoring.
4. Provide a child-friendly interface.
5. Record and summarize children's progress.
6. Provide visual communication resources.
7. Implement account authentication and access control.

### 6. Database Design

The system uses a relational database named `visual_schedule_system`.

The database contains the following main tables:

| Table | Purpose |
|---|---|
| users | Stores registered user information and account roles. |
| children | Stores child profile information associated with users. |
| activities | Stores available activities for schedule creation. |
| schedules | Stores schedule information for individual children. |
| schedule_items | Stores individual activities assigned to schedules, including their times and order. |
| tasks | Stores assigned tasks, due dates, priorities, and statuses. |
| task_completions | Stores task completion records. |
| communication_categories | Stores communication card categories. |
| communication_cards | Stores visual communication card information. |
| progress_records | Stores children's progress summaries. |

#### 6.1 Database Relationships

The database uses primary keys and foreign keys to connect related records.

Main relationships include:

- One user can manage multiple child profiles.
- One child can have multiple schedules.
- One schedule can contain multiple schedule items.
- Activities can be referenced by multiple schedule items.
- One child can have multiple assigned tasks.
- One task can have completion records.
- One communication category can contain multiple communication cards.
- One child can have multiple progress records.

### 7. System Modules

#### 7.1 Authentication Module

Responsible for user registration, login, logout, and session management.

Main functions:
- Register new accounts.
- Hash passwords before storing them.
- Verify passwords during login.
- Create authenticated user sessions.
- Restrict access to protected pages.
- Destroy sessions during logout.

#### 7.2 Caregiver Dashboard

Provides the main navigation interface and access to the application's modules.

#### 7.3 Child Profile Module

Handles child profile creation, retrieval, updating, and deletion.

The module associates child records with the authenticated user.

#### 7.4 Visual Schedule Module

Manages schedules and their associated activities.

Schedule information is stored in the schedules table, while individual scheduled activities are stored in schedule_items.

#### 7.5 Task Management Module

Handles task creation, retrieval, modification, deletion, and completion tracking.

Tasks are associated with child profiles.

#### 7.6 Child View Module

Provides a simplified interface for displaying schedules and tasks intended for child interaction.

#### 7.7 Progress Tracking Module

Uses task-related information and progress records to monitor task completion and maintain progress summaries.

#### 7.8 Communication Module

Organizes communication cards into categories and provides access to their associated visual and text information.

#### 7.9 Settings Module

Allows authenticated users to update available profile information and account preferences.

### 8. Database Connection

The application uses PHP Data Objects (PDO) to communicate with the database.

The connection configuration is maintained in:

`back_end/config/database.php`

Example connection:

```php
$host = "localhost";
$dbname = "visual_schedule_system";
$username = "root";
$password = "";

$pdo = new PDO(
    "mysql:host=$host;dbname=$dbname;charset=utf8mb4",
    $username,
    $password
);

$pdo->setAttribute(
    PDO::ATTR_ERRMODE,
    PDO::ERRMODE_EXCEPTION
);
```

PDO provides a consistent interface for database operations and supports prepared statements.

### 9. Security Implementation

The system incorporates several basic security practices.

**Password Hashing**

Passwords are stored using PHP's password hashing functions rather than plain text.

**Prepared Statements**

PDO prepared statements are used for database queries to reduce SQL injection risks.

**Session Management**

Authenticated users are identified through PHP sessions.

**Access Control**

Protected pages check whether the user has an authenticated session before allowing access.

**Input Validation**

User-submitted information is checked before database operations.

**Output Escaping**

HTML output is escaped to reduce the risk of cross-site scripting.

### 10. Installation and Configuration

#### 10.1 Requirements

- XAMPP
- PHP
- MySQL/MariaDB
- phpMyAdmin
- Web browser
- Project source code

#### 10.2 Installation Steps

1. Install XAMPP.
2. Place the project folder inside `htdocs`.
3. Start Apache and MySQL through the XAMPP Control Panel.
4. Open phpMyAdmin.
5. Create or import the `visual_schedule_system` database using the provided SQL schema.
6. Configure the database connection file.
7. Open the application through the local server.

Application URL:

`http://localhost/W_B_C_S_S/front_end/index.php`

### 11. GitHub Version Control and Collaboration

GitHub is used to manage the source code and coordinate team development.

**Development Workflow**

4. Submit a Pull Request targeting the main branch.

6. Merge approved changes into the main branch.

The main branch serves as the central version of the project.
